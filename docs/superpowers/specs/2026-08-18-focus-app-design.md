# 防拖延工具 —— 设计文档（第一阶段）

日期：2026-08-18

## 一、背景与问题

用户连续多天拖延任务，白天工作被手机打断（刷手机脱离专注），熬夜时也忍不住刷手机（约一半发生在电脑前切换到刷手机/网页，一半发生在已经上床后）。以前装过同类工具（番茄TODO、Forest、Cold Turkey、打卡类小程序等），但都是"新鲜劲一过就弃用"，没有形成长期习惯。

用户另有一个 Obsidian 个人工作台（课表、备考倒计时、任务管理、备忘录、番茄钟、小红书灵感库），因为 Obsidian Sync 太贵、电脑手机同步体验不好而想合并重做。经讨论后决定：**分阶段做**。本设计文档只覆盖第一阶段——平台地基 + 防拖延核心模块。学习工作台（课表/备考倒计时/任务管理/备忘录）作为第二阶段，接入同一平台架构，不在本文档范围内。小红书灵感库维持原有的飞书多维表格方案（已在另一份设计中确定，暂停实施中），与本项目无关，不合并。

## 二、范围（第一阶段）

**包含：**
- 电脑端 + 手机端共用的防拖延核心功能（专注仪式、数据看板、睡前签到）
- 账号登录与跨设备数据同步
- 电脑端可执行文件（exe）、手机端网页

**明确不包含（MVP 边界，后续按实际使用效果再评估是否加）：**
- 专注期间硬拦截分心网站/应用
- 夜间推送提醒
- 真人监督/分享打卡
- Windows 开机自启动
- 学习工作台（课表/备考倒计时/任务/备忘录）——第二阶段
- 小红书灵感库——独立项目，不合并

## 三、整体架构

一个纯前端网页（单页应用，响应式布局），PC 和手机共用同一套界面：

- **电脑端**：用 [nativefier](https://github.com/nativefier/nativefier)（开源现成工具）把网页打包成 Windows exe，双击运行，独立窗口 + 图标，不需要自己开发原生桌面程序。用户先固定到任务栏/桌面手动打开，暂不做开机自启动。
- **手机端**：直接用手机浏览器打开网址，添加到主屏幕，当作 app 使用。
- **数据同步**：使用 Supabase（免费额度）作为云端存储和登录服务。全程只服务一个用户，邮箱+密码登录一次，两端保持登录状态，长期免重复登录。

选择这个方案而非完整自建原生应用或 Flutter 全端方案，是因为改动成本最低——网页代码一改，两端同时生效，不需要维护 Windows 桌面构建工具链，适合这种"效果不好要能快速调整"的个人工具。

## 四、核心功能模块

### 1. 专注仪式（开场用，电脑/手机通用界面）

- 输入任务名（必填）
- 选择专注时长：25/45/60/90 分钟预设 + 自定义分钟数输入
- 开始后圆环式进度展示，支持暂停/继续/重置/跳过
- 结束（无论是正常跑完还是中途手动停止）都记一条记录：任务名、计划时长、实际时长、是否完整跑完
- 专注期间**不**做任何网站/应用的强制拦截

### 2. 数据看板

- 今日专注记录列表
- 当前连续天数
- 日 / 周 / 月三个维度的统计

### 3. 睡前签到（手机端为主要使用场景，同一页面 PC 也能打开）

- 如果当天还没有专注记录，可手动"今天做到了 / 没做到"签到
- 可选填写"明天第一件要做的事"
- **不**做定时推送提醒，靠用户自己养成打开习惯

### 4. 连续天数规则

- **宽松判定**：当天只要有一条专注记录（不论是否完整跑完）或一次手动签到，就算这天达标
- 断掉后：直接归零重新开始，界面上不做额外的"最好成绩"记录或安慰性提示，就是直白地变回 0

## 五、数据模型

单张 `sessions` 表，字段：

| 字段 | 说明 |
|---|---|
| id | 本地生成的唯一ID（用于去重，避免网络重试导致重复计数）|
| type | `focus`（专注记录）或 `checkin`（手动签到）|
| task_name | 任务名（专注记录必填，签到记录可为空）|
| planned_minutes | 计划专注分钟数（仅 focus 类型）|
| actual_minutes | 实际专注分钟数（仅 focus 类型）|
| completed | 是否完整跑完（仅 focus 类型）|
| note | 备注（签到时"明天第一件事"填在这里）|
| created_at | 时间戳 |

连续天数由这张表按日期去重直接计算得出，不需要额外维护"streak"字段。

## 六、账号与同步

- Supabase 邮箱+密码登录，单用户，登录后长期保持会话
- 每次开始/结束专注、每次签到，操作完成后立刻写入云端
- 打开页面时拉取云端最新数据刷新看板，保证电脑/手机两端看到的数据一致

## 七、异常处理

- **断网**：先写入本地 localStorage，页面提示"离线中，稍后自动同步"；网络恢复后自动补传，避免因为一次断网漏记打断连续天数
- **登录过期**：提示重新登录，本地未同步数据不清空，登录后照常补传
- **重复提交**：本地生成的唯一ID保证同一条记录不会被重复插入云端

## 八、验证方式

个人工具，不搭建自动化测试框架，手动验证以下流程：

1. 电脑上完成一次专注，确认记录成功写入云端
2. 手机浏览器登录同一账号，确认能看到电脑上刚才的记录及更新后的连续天数
3. 断网状态下操作，确认本地不丢失数据，网络恢复后自动补传
4. 用 nativefier 打包后，双击生成的 exe，确认能正常打开、图标显示正常

## 九、已知风险

- 用户过去多次因为"新鲜劲过了就忘了打开"而弃用同类工具。本版本没有做开机自启动等强提醒机制，只是固定到任务栏/桌面。如果使用一段时间后发现还是容易忘记打开，需要回来加强开场触发机制（如自启动、系统级提醒等）。
